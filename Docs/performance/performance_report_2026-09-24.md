## 1. 测试范围

本次重新测试包括：

- 上电后未解锁空载基线；

测试时电机电源未接。飞控通过 MAVLink 解锁，压力测试结束后自动下锁。

## 2. 总体结论

1. 60 秒组合满载时 CPU 占用为 **43.7%**，Idle 为 **56.3%**，处理器仍有明显余量。
2. 30 分钟压力测试共接收 **2,405,433** 个 MAVLink 包，飞控源前向序号丢包为 **0**，没有复位或通信中断。
3. SD 共写入 **102,454,536 B**、入队 **322,184** 帧；丢帧、丢字节、非法帧、写错误和同步错误均为 **0**。
4. BMI088 样本到控制任务开始的长期统计为 **93/109.097/530 us**，分别表示最短、平均和最长。
5. 姿态任务完整工作耗时为 **18.097/63.234/484.160 us**。主要长尾仍来自自适应陷波 FFT，以及 ESKF 预测和观测更新。
6. SDMMC 中断长期执行时间为 **2.570/3.794/44.097 us**。CMD12 收尾在低优先级 SD 任务中执行，不占用 SDMMC ISR。
7. Heap 历史最低剩余 **4200 B**；所有任务栈均保持正余量，没有发现栈耗尽。
8. 上位机单元测试 **23/23** 通过，生产构建通过；30 分钟 HIL 测试无丢步、无警告。
9. 固件 CTest 为 **7/11** 通过，4 项失败来自测试脚本仍依赖旧接口或旧字符串。默认全目标构建还会被既有格式差异拦截。

临界区计时覆盖 `taskENTER_CRITICAL()` 的最外层 BASEPRI 窗口；优先级 0～4 的高紧急度中断仍可在其中抢占，因此它是“FreeRTOS 可管理中断被屏蔽的墙钟时间”，不是 PRIMASK 全局关中断时间。P50/P95/P99/P99.9 上界分别为 1/1/2/2 us，最长 9.555 us，没有发现毫秒级关中断。

D-cache 已开启。热缓存相对冷缓存约快 1.50 倍，D2 非缓存访问时间约为热缓存的 6.99 倍。

Cortex-M7 没有供本工程直接读取的通用 D-cache hit/miss 计数器，因此本报告不提供推测性的“缓存命中率”。

### 8.2 SystemView

本次生成两份新的满载原始轨迹：

- `retest-systemview-full-load-20260924.SVDat`：9,330,897 B；
- `retest-systemview-snapshot-run-20260924.SVDat`：9,775,777 B。

文件包含 FreeRTOS、Cortex-M7、任务和 ISR 事件描述，可直接在 SystemView GUI 中打开。RTT 输出速率空载约 167–179 KB/s，满载约 230–261 KB/s。

#### 优先级结论

SystemView 中显示的 FreeRTOS 优先级没有颠倒：**任务优先级数值越大越高**。当前固定抢占顺序为：

`Attitude(54) > control(53) > sensor_hub(52) > uav_cmd(51) > mav_rx(50) > usb_tx(49) > data_router(48) > Timer Service(47) > sd_card(46) > performance(45) > Idle(0)`。

启动任务为 55，但初始化完成后自删除，不属于稳定运行集合。全部业务任务优先级唯一且连续，不存在同优先级时间片导致的顺序不确定；姿态、控制和传感器链优先于通信与 SD，当前排序合理。

NVIC 中断优先级与任务优先级的数字方向相反：**中断数值越小越高**，不能把 SystemView 的 Task Prio 与 NVIC 数字直接横向比较。关键关系为 BMI088 DRDY=1、BMI270 DRDY=2、DMA/可调用 FreeRTOS 的中断=5～8、PendSV=15。BMI088/BMI270 的高紧急度 EXTI 只锁存时间戳并启动 DMA，不调用 FreeRTOS API；真正通知任务的 DMA 中断不高于 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY=5`，符合 Cortex-M/FreeRTOS 约束。

抢占关系可以压缩表示为：链中任一左侧任务进入 Ready 后都可抢占其右侧所有任务；所有可屏蔽外设 ISR 又可抢占任意任务。BASEPRI 临界区仅屏蔽 NVIC 数值 5～15，高紧急度 0～4 仍可嵌套执行。

#### SystemView 当前能力边界

- 任务创建、任务切换、Ready/Blocked 和 ISR 进入/退出事件有效，因此任务优先级、运行时间线和抢占关系可信；
- 为控制 RTT 带宽，工程主动关闭了高频 queue、semaphore 和 task-notification trace 宏，所以仅凭当前 `.SVDat` 不能完整重建通知合并、队列等待和互斥量因果链；这些数值改由目标侧 DWT 统计给出；
- `traceTASK_PRIORITY_INHERIT` 仍有效，并由目标侧累计到 186 次；没有发现持续优先级倒置；
- SystemView 任务创建事件使用创建时的初始 SP 与栈底之差作为 StackSize，会比实际分配栈略小，因此栈余量以 `uxTaskGetStackHighWaterMark()` 的性能快照为准，不使用 GUI 的 Stack Information 做安全结论。

SystemView 4.10b 的无窗口 CSV 导出在本机不能正常结束，因此数值汇总使用目标侧 DWT/FreeRTOS 快照，原始轨迹保留用于 GUI 时间线检查。

SystemView 构建只用于采集。测试结束后目标板已经恢复正式性能固件，自动追踪关闭。

## 11. 当前仍未覆盖的项目

- 物理中断响应时间：需要逻辑分析仪同时测量传感器 DRDY 与 ISR 测试 GPIO，或使用定时器 Input Capture。
- DRDY 到 PWM/DSHOT 引脚的真实端到端延迟：需要外部仪器和实际输出信号。
- D-cache 真实命中率：当前 MCU 没有可直接使用的命中/未命中计数器。
- 慢卡、坏卡、近满盘、严重碎片化和飞行中拔卡：本次没有执行介质故障注入。
- SBUS 丢帧和失联恢复：测试时未接收机或信号发生器。
- 带电电机、ESC 和机械系统：本次电机电源未接。
- ISR 嵌套深度/嵌套组合：SystemView 可观察具体片段，但当前目标侧尚未累计“最大嵌套层数”和组合计数。
- Tick/Timer Service 回调迟到：当前没有有效业务软件定时器回调，无法制造有意义的回调延迟样本。
- 队列和环形缓冲 occupancy 分布：已有峰值与丢弃计数，未增加每档驻留直方图。
- 故障注入：未执行 IMU 停更、光流突发、USB 拔插、SD 卡拔出/写满、CPU 人工过载等破坏性测试。
- 60%～90% CPU 人工过载：本次真实组合负载没有达到该区间；不得把 43.7% 的真实满载结果外推为过载稳定性。
- 最坏点前后因果回溯：当前 DWT 给出准确长尾数值，SystemView 原始轨迹可人工定位，但尚未建立自动保存长尾前后 1～5 ms 事件窗口的触发器。
